**Findings**

BUG-001 (Critical): The spec assumes a full in-memory dataset, but the current fetch path is paginated by default. `getProjects(true)` still hits a 50-project server limit, and `getTasks(...states...)` still hits a 100-task limit, so sidebar counts, overdue/no-task filters, dashboard totals, and `?id=` deep links will silently break for larger accounts. Refs: [spec](/Users/peterpitcher/Cursor/OJ-Planner2.0/docs/superpowers/specs/2026-04-07-projects-page-redesign-design.md#L157), [spec](/Users/peterpitcher/Cursor/OJ-Planner2.0/docs/superpowers/specs/2026-04-07-projects-page-redesign-design.md#L181), [apiClient.js](/Users/peterpitcher/Cursor/OJ-Planner2.0/src/lib/apiClient.js#L25), [apiClient.js](/Users/peterpitcher/Cursor/OJ-Planner2.0/src/lib/apiClient.js#L65), [projects route](/Users/peterpitcher/Cursor/OJ-Planner2.0/src/app/api/projects/route.js#L60), [tasks route](/Users/peterpitcher/Cursor/OJ-Planner2.0/src/app/api/tasks/route.js#L58).

BUG-002 (Critical): Notes loading is race-prone. The spec fetches notes on project select and appends notes locally, but without an abort/version check a slow response for project A can overwrite project B after a rapid switch, and a note created on A can append into B’s visible list. Existing `ProjectDetailDrawer` already uses this unsafe pattern, and `loadData()` cannot revert note state because notes are not part of initial load. Refs: [spec](/Users/peterpitcher/Cursor/OJ-Planner2.0/docs/superpowers/specs/2026-04-07-projects-page-redesign-design.md#L149), [spec](/Users/peterpitcher/Cursor/OJ-Planner2.0/docs/superpowers/specs/2026-04-07-projects-page-redesign-design.md#L163), [ProjectDetailDrawer.jsx](/Users/peterpitcher/Cursor/OJ-Planner2.0/src/components/Projects/ProjectDetailDrawer.jsx#L119), [ProjectDetailDrawer.jsx](/Users/peterpitcher/Cursor/OJ-Planner2.0/src/components/Projects/ProjectDetailDrawer.jsx#L150), [ProjectDetailDrawer.jsx](/Users/peterpitcher/Cursor/OJ-Planner2.0/src/components/Projects/ProjectDetailDrawer.jsx#L227), [ProjectsView.jsx](/Users/peterpitcher/Cursor/OJ-Planner2.0/src/components/Projects/ProjectsView.jsx#L490).

BUG-003 (High): The notes API contract in the spec does not match the real `apiClient`. `apiClient.getNotes({ projectId })` is wrong for the current positional signature and will serialize as `projectId=[object Object]`; `createNote()` and `getNotes()` also return wrapped JSON, not a raw note array/object. If implemented literally, notes will come back empty or the UI will append malformed `{ data: ... }` entries. BUG-004 (High): If the redesign follows the current `ProjectsView` state shape, optimistic failure recovery will desync the sidebar and workspace. The current view stores whole `selectedProject` / `selectedTask` objects separately, while `loadData()` only refreshes the collections; after a failed inline edit, the sidebar can show reverted server data while the main panel still shows stale optimistic values. Refs: [spec](/Users/peterpitcher/Cursor/OJ-Planner2.0/docs/superpowers/specs/2026-04-07-projects-page-redesign-design.md#L119), [spec](/Users/peterpitcher/Cursor/OJ-Planner2.0/docs/superpowers/specs/2026-04-07-projects-page-redesign-design.md#L175), [ProjectsView.jsx](/Users/peterpitcher/Cursor/OJ-Planner2.0/src/components/Projects/ProjectsView.jsx#L475), [ProjectsView.jsx](/Users/peterpitcher/Cursor/OJ-Planner2.0/src/components/Projects/ProjectsView.jsx#L490).

BUG-005 (High): The client-side task cache is not stable under regrouping. The spec says tasks are fetched once, grouped by `project_id`, and later “task updated” just patches local state, but current code already has to fully reload after task moves because regrouping is required; if a task changes `project_id` in `TaskDetailDrawer`, it must be removed from the old project and inserted into the new one, not mutated in place. BUG-006 (Medium-High): The overdue metric is easy to double-count. The filter definition is a project-level OR, but the dashboard copy says “projects past due + projects with overdue tasks”; if those are summed independently, one project can count twice while only appearing once in the filtered list. Refs: [spec](/Users/peterpitcher/Cursor/OJ-Planner2.0/docs/superpowers/specs/2026-04-07-projects-page-redesign-design.md#L89), [spec](/Users/peterpitcher/Cursor/OJ-Planner2.0/docs/superpowers/specs/2026-04-07-projects-page-redesign-design.md#L199).

BUG-007 (Medium): The overdue rule is not time-zone safe. The spec introduces plain `due_date < today` checks even though the codebase already has multiple competing date rules and a dedicated London start-of-day helper to avoid DST/off-by-one issues; implementing another comparison path will make sidebar filters disagree with task badges around midnight. Refs: [spec](/Users/peterpitcher/Cursor/OJ-Planner2.0/docs/superpowers/specs/2026-04-07-projects-page-redesign-design.md#L39), [spec](/Users/peterpitcher/Cursor/OJ-Planner2.0/docs/superpowers/specs/2026-04-07-projects-page-redesign-design.md#L199), [dateUtils.js](/Users/peterpitcher/Cursor/OJ-Planner2.0/src/lib/dateUtils.js#L75), [dateUtils.js](/Users/peterpitcher/Cursor/OJ-Planner2.0/src/lib/dateUtils.js#L138), [projectHelpers.js](/Users/peterpitcher/Cursor/OJ-Planner2.0/src/lib/projectHelpers.js#L3).

BUG-008 (Medium): The area dropdown source and filter semantics do not line up. `/api/areas` returns case-insensitive deduped areas from both tasks and projects, but the spec filters by exact `project.area === selectedArea`, so the dropdown can offer values that match no project and can also hide projects whose area differs only by casing. Refs: [spec](/Users/peterpitcher/Cursor/OJ-Planner2.0/docs/superpowers/specs/2026-04-07-projects-page-redesign-design.md#L48), [spec](/Users/peterpitcher/Cursor/OJ-Planner2.0/docs/superpowers/specs/2026-04-07-projects-page-redesign-design.md#L194), [areas route](/Users/peterpitcher/Cursor/OJ-Planner2.0/src/app/api/areas/route.js#L18), [areas route](/Users/peterpitcher/Cursor/OJ-Planner2.0/src/app/api/areas/route.js#L32).

BUG-009 (Medium): URL sync is underspecified once a selected project becomes hidden. The spec says the main panel should revert to dashboard if filters hide the selected project, but it never says whether `?id=` is cleared, whether `showCompleted` should auto-enable for completed deep links, or what happens after refresh when the URL still points at a hidden project. Refs: [spec](/Users/peterpitcher/Cursor/OJ-Planner2.0/docs/superpowers/specs/2026-04-07-projects-page-redesign-design.md#L44), [spec](/Users/peterpitcher/Cursor/OJ-Planner2.0/docs/superpowers/specs/2026-04-07-projects-page-redesign-design.md#L75), [spec](/Users/peterpitcher/Cursor/OJ-Planner2.0/docs/superpowers/specs/2026-04-07-projects-page-redesign-design.md#L181).

BUG-010 (Medium-Low): Empty states are incomplete for the combinations this design creates. The spec covers “no project selected” and hidden empty task groups, but not “no projects at all”, “only completed projects while toggle is off”, “current filter/area has zero visible projects”, or “selected project has no tasks and no notes”, so the UI will end up as empty chrome with no guidance.
